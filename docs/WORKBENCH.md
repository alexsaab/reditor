# reditor: команды и рабочие панели

**Ctrl+P** открывает поиск файлов проекта, **Ctrl+Shift+P** и **Ctrl+G** — палитру команд и плагинов. Введите часть имени или идентификатора, затем Enter или щелчок. Esc закрывает окно, Ctrl+U очищает ввод, стрелки/PageUp/PageDown/колесо прокручивают. **Ctrl+Alt+P** показывает недавние проекты, **Ctrl+Alt+O** открывает браузер папок для выбора проекта. При запуске без аргументов редактор восстанавливает последний открытый проект; явно переданная папка или `--workspace` имеет приоритет.

В браузере папок Enter или двойной щелчок открывает выбранный каталог, Backspace поднимается на уровень выше, а `O` или кнопка **Выбрать эту папку** открывает текущий каталог как проект.

Каждая папка, открытая из командной строки или через браузер каталогов, добавляется в `~/.reditor/projects.json` (до 20 последних). Выбор в списке переключает рабочую папку, сохраняет вкладки текущего проекта в его `.reditor/session.json` и восстанавливает вкладки выбранного проекта. Ctrl+O принимает путь к файлу или папке; путь к файлу открывает обычную вкладку. В некоторых терминалах Ctrl+Shift+P совпадает с Ctrl+P, поэтому для палитры есть Ctrl+G.

В проводнике F2 переименовывает выбранный файл или папку, Delete удаляет их после подтверждения. Перетаскивание файла/папки на папку перемещает элемент; существующие элементы назначения не перезаписываются.
Правый клик по файлу или папке открывает контекстное меню с действиями открытия, переименования и удаления.
Это меню также копирует абсолютный путь или путь относительно корня проекта в системный буфер обмена. Переименование и удаление применяются как к файлам, так и к папкам; удаление папки удаляет её содержимое.

## Размеры панелей

Удерживайте левую кнопку мыши на границе и перетаскивайте: между проводником и редактором — ширина проводника; между двумя областями редактора — их соотношение; верхняя граница нижнего терминала — высота терминала. Границы отмечены ↔ / ↕. Можно менять размер исходника рядом с Markdown или Mermaid. Минимальные размеры защищают панели от полного схлопывания; при уменьшении окна размеры ограничиваются доступным местом.

С клавиатуры откройте **Ctrl+G** и выберите `terminal.grow` / `terminal.shrink`, `layout.explorer.grow` / `layout.explorer.shrink` или `layout.split.grow` / `layout.split.shrink` (меняется ширина левой области). `layout.reset` возвращает исходные размеры. Команды можно назначить на свои клавиши в `[keybindings]`. Размеры действуют до выхода из редактора.

## Нижний терминал и Rust

**F10** показывает нижнюю панель и переводит туда фокус; повторное нажатие при фокусе в терминале скрывает её. Процессы продолжают работать. Щелчок по коду возвращает ввод редактору, щелчок по терминалу — процессу. Внизу есть вкладки и кнопки нового терминала, сборки, запуска, тестов, Clippy, остановки, закрытия и палитры.

PTY запускает оболочку из `$SHELL` (Unix) или PowerShell (Windows), поддерживает ANSI, Unicode и stdin. Ctrl+C передаётся приложению. Alt+1…9 выбирает вкладку, колесо и Shift+PageUp/PageDown прокручивают историю. F10 и Ctrl+Q обслуживает редактор. Команды `terminal.new`, `terminal.stop`, `terminal.close`, `terminal.grow`, `terminal.shrink` управляют панелью. При выходе процессы останавливаются.

Откройте каталог проекта с Cargo.toml:

```sh
./target/release/reditor /path/to/rust-project --lang ru
```

Готовый небольшой пример: `./target/release/reditor examples/rust-app --lang ru`. Нажмите Ctrl+F11 для сборки, F11 для запуска и введите имя в нижнем терминале. Через `cargo.args` можно передать имя аргументом и проверить запуск без запроса ввода.

| Действие | Команда |
| --- | --- |
| Сборка | Ctrl+F11 / `cargo.build` |
| Запуск приложения | F11 / `cargo.run` |
| Тесты | `cargo.test` |
| Clippy | `cargo.clippy` |
| Проверка | `cargo.check` |
| Пакет workspace / bin | `cargo.package` / `cargo.target` |
| Debug или release | `cargo.profile` |
| Аргументы приложения | `cargo.args` |
| Перейти к строке из вывода | `cargo.locations` |

Выбор целей строится через cargo metadata. Аргументы, например `"Привет мир" --port 8080`, разбираются в argv без подстановок оболочки. Cargo использует сохранённые файлы: сначала Ctrl+S или `file.save_all`. `cargo run` включает сборку. Каждая задача получает отдельную вкладку; выбранные профиль, пакет, bin и аргументы действуют до выхода. Старый Ctrl+B запускает фоновый cargo check, F8 открывает его вывод.

## Rust-analyzer

```sh
rustup component add rust-analyzer rust-src
```

На этой машине компоненты установлены. Сервер автоматически запускается для сохранённых `.rs`. Доступны `lsp.complete` (Ctrl+Space), `lsp.hover` (Ctrl+K), `lsp.definition` (F12), `lsp.references` (Shift+F12), `lsp.rename`, `lsp.actions`, `lsp.diagnostics`, `lsp.restart`. При перехвате клавиш терминалом используйте Ctrl+G. Первичная загрузка проекта занимает время.

Ошибки отмечаются у номеров строк; сообщение для строки курсора выводится на границе панели. Синтаксические сообщения обновляются из буфера, проверки компилятора выполняются после сохранения. Переименование и исправления проходят просмотр, применяются в буферы и сохраняются через `file.save_all`.

Документация: [LSP](https://microsoft.github.io/language-server-protocol/specifications/lsp/3.17/specification/), [rust-analyzer](https://rust-analyzer.github.io/book/features.html).

## Поиск, окна, Git и Mermaid

`files` открывает файл по части имени, `search.project` ищет текст с переходами. `replace.file` (Ctrl+H) и `replace.project` запрашивают текст и замену, затем показывают изменения. Замена может быть пустой. Enter применяет результат в буферы; файлы на диске меняются после сохранения. Изменение исходника после подготовки просмотра отменяет применение.

`split.next` (Ctrl+\\) показывает два редактируемых файла с выбором панели мышью. `split.preview` показывает исходник рядом с Markdown, `split.diagram` — с Mermaid. Просмотр обновляется из буфера; Mermaid перестраивается в фоне не чаще раза в 600 мс. `split.close` закрывает вторую панель.

`git.status` показывает файлы и сравнение выбранного файла; `git.diff` — общее сравнение. Ветка и изменённые сохранённые строки обновляются в фоне. `git.stage` добавляет выбранный файл в индекс, `git.commit` запрашивает сообщение и запускает коммит в терминале. Коммит использует уже подготовленный индекс. Git и автор коммита настраиваются обычными средствами Git.

`diagram.list` выбирает блок, `diagram.labels` ищет подпись и прокручивает к ней, `diagram.connections` показывает строки связей исходника. После F9: **/** — поиск подписей, **S** — SVG, **P** — PNG. Экспорт доступен через `diagram.svg` / `diagram.png`: укажите новый относительный или абсолютный путь после окончания построения. Существующие файлы защищены от перезаписи.

## Lua: PHP, Git, FTP/SFTP/FTPS

Плагины устанавливаются в `~/.reditor/plugins` для пользователя или `<проект>/.reditor/plugins` для проекта и загружаются автоматически. Конкретные поля проектной конфигурации имеют приоритет над общими. Исходники плагинов редактируются как обычные файлы; F5 перечитывает их. Значки плагинов находятся в левой панели; клик открывает их команды. Инструкции: [PLUGINS_REMOTE.md](PLUGINS_REMOTE.md), [FORMATTER.md](FORMATTER.md).

В палитре `settings.user` открывает общие настройки, `settings.project` — проектные. `remote.settings.user` / `remote.settings.project` открывают общие и проектные профили серверов. Настройки PHP и Git записываются в `[plugin_settings.php]` и `[plugin_settings.git]`.

## Восстановление и настройки

Вкладки, курсоры, прокрутка и несохранённые буферы записываются в `.reditor/session.json` каждые две секунды и при выходе. При запуске сессия восстанавливается; явные файлы открываются дополнительно. Исходники не сохраняются автоматически. Конфликты внешнего изменения файла проверяются после восстановления. Последние изменения менее чем за две секунды до аварии могут не попасть в копию.

`settings` открывает `.reditor/config.toml`; настройки применяются после сохранения. `settings.theme`, `settings.indent`, `settings.wrap` меняют тему, отступ и перенос. Размер шрифта задаётся самим терминалом.

```toml
language = "ru"
theme = "base16-ocean.dark"
indent = 4
wrap = false
rust_analyzer = "rust-analyzer" # пустая строка отключает сервер

[keybindings]
"Alt+b" = "cargo.build"
"Alt+r" = "cargo.run"
"Alt+f" = "files"
```

Темы: base16-ocean.dark, base16-eighties.dark, InspiredGitHub, Solarized (dark), Solarized (light). Комбинации: Ctrl+, Alt+, Shift+, затем строчная буква, Space, Enter, Tab или F1…F12. Некоторые терминалы не различают Ctrl+Shift+буква и Ctrl+буква. Пользовательские процессы внутри терминала получают свои обычные клавиши.

## Ограничения и проверки

Поиск/замена учитывают Git-исключения и пропускают `target`, `node_modules`, `.reditor`, `.git`, `.browsers`, ссылки и бинарные файлы. Индекс — до 20 тысяч файлов, поиск — до 5000 совпадений, неоткрытые файлы — до 2 MiB. Поиск текстовый, с учётом регистра. История терминала — 10 тысяч строк, журнал — около 2 MiB. LSP snippets, создание/удаление/переименование файлов из code actions, передача mouse-протокола и графических изображений вложенным приложениям пока не реализованы. Для выделения вывода средствами родительского терминала обычно используется Shift + мышь.

```sh
cargo fmt --check
cargo clippy --all-targets --locked -- -D warnings
cargo test --locked
cargo test real_rust_analyzer -- --ignored
cargo build --release --locked
python3 scripts/smoke_tui.py target/release/reditor --mermaid
python3 scripts/smoke_studio.py target/release/reditor
```

Сценарии используют временные проекты и PTY на macOS/Linux. Проверка LSP требует установленных компонентов. ConPTY проверяется отдельно в интерактивном Windows-терминале.
