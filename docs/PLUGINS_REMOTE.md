# Lua-плагины и настройки reditor 0.3

## Установка и приоритет

```sh
# Для всех проектов пользователя:
./target/release/reditor --install-plugin php --install-plugin git --install-plugin remote --scope user

# Только в указанный проект:
./target/release/reditor --workspace /path/to/project --install-plugin php --install-plugin git --install-plugin remote --scope project
```

Установщик копирует Lua-исходники и manifest из встроенных ресурсов бинарника. Node.js для этих трёх плагинов не нужен. Повторная установка существующего плагина выдаёт ошибку и сохраняет ваши файлы. Переносите нужные изменения из `bundled` вручную. F5 перечитывает исходники, команды и manifest.

| Что хранится | Пользователь | Проект |
| --- | --- | --- |
| Настройки редактора и плагинов | `~/.reditor/config.toml` | `<проект>/.reditor/config.toml` |
| Lua/JS/TS-плагины | `~/.reditor/plugins/<имя>/` | `<проект>/.reditor/plugins/<имя>/` |
| Профили FTP/SFTP/FTPS | `~/.reditor/connections.toml` | `<проект>/.reditor/connections.toml` |
| Проверенные SSH-ключи серверов по умолчанию | `~/.reditor/known_hosts` | Можно задать `known_hosts` в профиле |
| Кэш удалённых файлов и исходные версии | — | `.reditor/remote/files`, `.reditor/remote/index.json` |
| Восстановление вкладок и буферов | — | `.reditor/session.json` |

`REDITOR_USER_DIR` позволяет разместить пользовательскую `.reditor` в другом месте. На Windows используется каталог пользователя из HOME или USERPROFILE. Проектные настройки переопределяют только заданные поля, включая вложенные настройки и сочетания клавиш. При одинаковом имени плагина приоритет: `--plugins` → проект → пользователь. Подключайте доверенные плагины: каталоги `.reditor/plugins` загружаются автоматически.

**Ctrl+G → `settings.user` / `settings.project`** открывает настройки как обычный файл. После Ctrl+S настройки редактора применяются; plugin_settings перечитываются перед командой. **Ctrl+Shift+P** открывает палитру, включая команды Lua-плагинов. Их названия переведены на RU/EN/DE/ES.

## PHP

Доступные команды: `php.template`, `php.outline`, `php.lint`, `php.run`, `php.server`.

- `php.template`: вставляет `<?php` и `declare(strict_types=1)` в пустой файл.
- `php.outline`: показывает строки объявлений классов, функций, интерфейсов, traits и enums. Это поиск шаблонов строк; он может включать объявления в комментариях и не заменяет PHP language server.
- `php.lint`: передаёт текущий буфер в PHP CLI через stdin и показывает проверку синтаксиса в фоне; сохранять файл перед проверкой не нужно.
- `php.run`: запускает сохранённый `.php` в нижнем терминале, поддерживает ввод и Ctrl+C. Выполняется локальная копия файла, в том числе для удалённых документов.
- `php.server`: запускает локальный сервер в корне проекта на `127.0.0.1`; вывод идёт в терминал. Остановка: Ctrl+C или `terminal.stop`.

Нужен PHP CLI в PATH либо путь к нему в настройках:

```toml
[plugin_settings.php]
php_binary = "php"
port = 8080
```

Сохраните это в общей или проектной `config.toml`. Подсветка `.php` уже обеспечивается редактором. PHP-плагин не устанавливает Composer или расширения PHP и не запускает код при открытии файлов.

## Git

Lua-плагин предоставляет `git.status`, `git.diff`, `git.stage`, `git.commit`, `git.log`. Он вызывает штатный Git через функции редактора; Rust-подсветка изменений и существующие Git-команды сохраняются.

`git.stage` предлагает выбрать изменённый файл; `git.commit` запрашивает сообщение и показывает процесс в нижнем терминале. `git.log` показывает историю с названиями веток/тегов. Коммит использует подготовленный индекс. Автор и репозиторий настраиваются обычным Git.

```toml
[plugin_settings.git]
log_limit = 50 # от 1 до 500
```

## FTP / FTPS / SFTP

**Ctrl+G → `remote.settings.user`** открывает общие подключения, **`remote.settings.project`** — проектные. Установщик создаёт файл с закомментированными примерами. Добавьте настоящий профиль, затем Ctrl+S:

```toml
[connections.my_server]
protocol = "sftp"
host = "server.example.org"
port = 22
user = "developer"
root = "/var/www"
key_file = "~/.ssh/id_ed25519"
known_hosts = "~/.ssh/known_hosts"
# key_passphrase_env = "REDITOR_KEY_PASSPHRASE"
# password_env = "REDITOR_SFTP_PASSWORD" # альтернатива key_file
```

SFTP работает через SSH/libssh2. Если не заданы key_file и password_env, используется SSH-agent. Неизвестный или изменённый ключ сервера отклоняется до аутентификации. Можно указать существующий проверенный `~/.ssh/known_hosts` или хранить проверенные записи в `~/.reditor/known_hosts` (значение по умолчанию). Самостоятельное принятие непроверенного ключа не выполняется. Относительные пути ключей, known_hosts и сертификатов разрешаются относительно каталога конкретного `connections.toml`; `~` означает домашний каталог.

```toml
[connections.hosting]
protocol = "ftps"
host = "ftp.example.org"
user = "developer"
root = "/public_html"
password_env = "REDITOR_FTPS_PASSWORD"
implicit_tls = false
# port = 21
# ca_file = "certificates/hosting-ca.pem"
```

`implicit_tls=false` — явный TLS, порт 21 по умолчанию. `true` — неявный TLS, порт 990. Обязательно шифруются контрольный канал и данные; сертификат проверяется. Для собственной CA укажите ca_file. FTP/FTPS используют команду **curl**, SFTP не зависит от поддержки SSH в curl.

Для обычного FTP используйте `protocol="ftp"`; он передаёт данные без TLS. Пароли и passphrase берутся из переменных окружения, значения не записываются в конфигурацию или аргументы процесса curl. Пример запуска:

```sh
read -s REDITOR_FTPS_PASSWORD
export REDITOR_FTPS_PASSWORD
./target/release/reditor /path/to/project --lang ru
```

Для одного имени подключения можно переопределить только root/port в проектном файле, сохранив общие host/user/ключи.

### Работа с файлами

1. **Ctrl+G → `remote.connect`**: выберите профиль.
2. Открывайте каталоги и файлы стрелками + Enter или мышью; `..` поднимается на уровень. Проводник удалённых файлов открывается в отдельном меню.
3. Редактируйте скачанный файл как обычный документ. **Ctrl+S** сохраняет локальный кэш и запускает фоновую отправку. Для повтора используется `remote.upload`.
4. `remote.browse` возвращает в удалённый каталог. `remote.mkdir` создаёт каталог; `remote.new_file` создаёт пустой файл в текущем каталоге.
5. `remote.reload` перечитывает файл, когда нет локальных изменений или ещё не отправленных правок.

Обозначения вкладки: **☁** — файл связан с сервером; **⇧** — локальная сохранённая версия отличается от последней подтверждённой серверной. **●** сохраняет обычное значение несохранённых правок буфера.

Каждый upload сначала сравнивает серверный текст с исходной версией. Если другой клиент изменил файл, отправка отменяется: локальные правки остаются в кэше. Перед заменой файл передаётся во временное имя, затем переименовывается и перечитывается для проверки. SFTP требует поддержки атомарного переименования сервером. FTP/FTPS используют RNFR/RNTO; абсолютная атомарность и замена существующего имени зависят от сервера. Сбой может оставить временный `.reditor-*` на сервере. Проверка не является серверной блокировкой: другой клиент всё ещё может изменить файл в коротком промежутке между сравнением и переименованием.

Повторные сохранения ставятся в очередь, последние правки одного файла заменяют более старую ожидающую отправку. После ошибки или выхода из редактора локальная копия сохраняется; при следующем открытии её можно отправить через `remote.upload`. Текстовый редактор работает с UTF-8 файлами до 8 MiB; двоичные файлы с NUL отклоняются. FTP поддерживает MLSD и запасной разбор Unix/DOS LIST. Время одной сетевой операции ограничивается `timeout_seconds` (по умолчанию 30, максимум 120).

## API для собственных Lua-плагинов

Manifest явно объявляет capabilities:

```toml
capabilities = ["php"]
```

Команда возвращает декларативный запрос:

```lua
return function(ctx)
    return { action = { kind = "php", command = "php.lint" } }
end
```

Разрешены только перечисленные выше операции `php`, `git` и `remote`. Редактор проверяет capability, затем выполняет запрос в фоне или PTY. Автоматические `on_open` / `before_save` не могут выполнять action. Непосредственный доступ Lua к io/os/require остаётся отключённым. ctx.settings объединяет `[settings]` manifest и `[plugin_settings.<имя>]` общей/проектной конфигурации. Поле `titles={ru="...",en="...",de="...",es="..."}` у команды локализует её название.

Документация протоколов и инструментов: [PHP CLI](https://www.php.net/manual/en/features.commandline.options.php), [curl FTP/FTPS](https://curl.se/docs/tutorial.html), [SSH known_hosts](https://docs.rs/ssh2/latest/ssh2/struct.KnownHosts.html).

## Проверки

`cargo test --locked` проверяет настройки, Lua, ограничения API, кэш и форматы каталогов. Реальные PHP-проверки: `cargo test --locked real_php_lua -- --ignored`. Для тестов протоколов создайте временное Python-окружение, установите `pyftpdlib paramiko pyopenssl` и выполните `python scripts/smoke_remote.py`: серверы работают только на localhost и удаляются вместе с временными данными.
